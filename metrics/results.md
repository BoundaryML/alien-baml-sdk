# Measurements

> **PROVISIONAL.** These numbers were measured while the machine was busy: the 1-minute load average was 1.8–3.6 during the run (18 cores). Ratios between programs measured in the same run are more reliable than absolute times, but treat both as provisional. Re-run `bench/run.sh` when `uptime` shows a load average below 2; this banner disappears when every sample was taken at or below it.

Cold start, resident memory, warm per-call latency, large-page decode, the cost of telemetry, installed size and Rust build time, for the four BAML SDKs and Alien's current SDKs (the incumbents). Generated by `bench/render.py` from [`raw/results.json`](raw/results.json); regenerate with (bench/run.py):

```sh
ALIEN_REF=/path/to/alien bench/run.sh --quiet-wait 60
```

**Machine:** 18 cores, 128 GB, macOS 27.0.1. Node v24.22.1, Python 3.14.4, go1.27.3 darwin/arm64, rustc 1.96.0 (ac68faa20 2026-05-25). **Measured:** 2026-10-26 16:20 PDT.

**Builds.** BAML 0.23.0 (release). Incumbents built by `bench/build.sh` from Alien commit `c5c3a30b3a71`: `@alienplatform/platform-api` (Speakeasy TypeScript, with the dependency versions Alien's `pnpm-lock.yaml` pins) and `alien-platform-api` (Progenitor Rust, default features: only the operations Alien itself calls). There is no Python or Go incumbent.

**Method.** Every request goes to `bench/fixed-server.mjs`, a zero-latency server on 127.0.0.1 (`GET /v1/managers/{id}` returns one Manager, `GET /v1/managers?limit=N` returns N of them). Every process gets an empty `BAML_HOME` and telemetry off; the driver fails if a process writes any file there. The exception is the [telemetry-on](#telemetry-on-the-default) rows, measured with telemetry as an application gets it by default. Go and Rust load the runtime library from a local path. Programs are interleaved round-robin so that a burst of load spreads over all of them, and the 1-minute load average is recorded with every sample. Tables show medians; ranges are the interquartile range (p25–p75).

**Quiet machine.** Before the measurements and before the Rust builds the driver waited up to 60 minutes for a 1-minute load average below 2 (`--quiet-wait`). Load when each section started: cold start 1.82 (after 4 min), warm-get ns/call 3.12, warm-helper ns/call 2.79, warm-noop ns/call 2.58, page 20 ms/call 2.69, page 2000 ms/call 2.71, rust builds 1.90 (after 20 min).

## Warm per-call latency

After a warm-up in each process: 3 processes × 5 batches of 400 sequential `managers.get` calls to the local server; the cost per call of each batch. `setup helper` (3 × 10 × 2000 calls) builds a CloudFormation link without any I/O, and `no-op` is a zero-argument BAML function that returns a constant, so it is the cost of crossing into the runtime and back.

| Program | `managers.get` µs | p25–p75 | Setup helper µs | No-op µs | Load |
|---|---|---|---|---|---|
| TypeScript | 234 | 224–242 | 121.7 | 8.9 | 2.5–3.1 |
| Incumbent TS | 83 | 76–98 | — | — | 2.5–3.6 |
| Python | 261 | 257–290 | 150.8 | 19.9 | 2.5–3.6 |
| Go | 234 | 227–275 | 144.8 | 20.7 | 2.5–3.6 |
| Rust | 209 | 192–212 | 135.8 | 14.4 | 2.5–3.6 |
| Incumbent Rust | 44 | 44–49 | — | — | 2.5–3.6 |

**Connections.** Every SDK keeps its connection open between calls. For 500 sequential `managers.get` calls in one process, each BAML SDK opened 1 TCP connection, Alien's TypeScript SDK 2 and its Rust SDK 1; as a control, Python's `urllib` opened one per request. The BAML runtime has reused its HTTP clients across requests since BAML 0.23.0 (BAML #5373). This is a one-off count on 2026-10-26, over plain HTTP to the local server (`GET /stats` on `bench/fixed-server.mjs`; `bench/run.sh` does not re-count), so the TLS handshake against `https://api.alien.dev` was not measured.

The setup helper's cost is mostly BAML code: compiling the region pattern on every call (a BAML constant can hold the compiled pattern since BAML 0.23.0, but the helper does not keep one, [gaps B17](../docs/gaps.md#b17)), building the link with string interpolation, which BAML 0.23.0 runs more slowly than `+`, and percent-encoding character by character in the interpreter. A setup link is built once per customer, so it does not matter there.

Where the large-page time goes (a one-off profile on 2026-10-26 with macOS `sample` and a symbolized build of the BAML 0.23.0 release commit, whose timings matched the published build; TypeScript, page of 2,000; `bench/run.sh` does not re-profile): about 72% of the call is inside the BAML runtime, the same work in every language. Of that runtime time, 6% turns the JSON text into typed values (`baml.json.decode`, one pass since 0.23.0), 35% converts those values into the tree the runtime hands to the host, 20% copies that tree once more, 21% encodes it as protobuf and 11% frees the copies; HTTP and BAML's garbage collection are about 2% each. The other 28% is the host side: decoding the protobuf and building the generated classes in JavaScript (24%), and V8's garbage collection (4%), whose helper threads spend about another 14% of the call's time in parallel. Python's host side is larger (pydantic models). In the 2026-10-21 profile (BAML 0.22.2), decoding the JSON was 56% of the runtime time; now handing the result to the host is most of it.

## Rust build time and generated code

Clean builds of the Rust bench program (`bench/rust`: the SDK and every dependency, in a fresh target directory, downloads fetched first) and of the same program on Alien's Progenitor client (`bench/incumbent-rust`), with default features (only the Platform operations Alien's own code calls) and with `full-api` (every Platform operation). "SDK only" then rebuilds just the generated SDK crate and the program. Seconds, median of 3 runs; the load average at the start of each run was 1.9–4.8, most of it from the previous build. The BAML SDK's Rust code is generated before the build (`baml generate`) and covers every Platform and Manager operation; Progenitor generates its client in a build script, so its times include generation.
